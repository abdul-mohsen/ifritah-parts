## 1. What the project is

A **Hyundai/KIA aftermarket parts search engine** written in Go (Gin). Given a part
number (OEM) or free text, it finds aftermarket alternatives, cross-references, vehicle
fitment, and substitution chains. Powers a React/Vite frontend.

**Backend stack:** Go 1.25 / Gin / PostgreSQL 55432 (owned catalog) / TecDoc MySQL
(21.5M OEM rows, 30M cross-refs, 651M vehicle linkages)

## 6. Root Cause — The Single Biggest Finding

TecDoc MySQL IS deployed and connected ("tecdoc":true on health endpoint).
The problem is which tables are actually queried:

| Table | Rows | Queried? |
|-------|-----:|---------|
| oem_number | 21.5M | YES |
| articles | 6.9M | YES |
| ambrand | 3.8K | YES |
| articlecrosses | 30M | NO — should be primary OEM fallback |
| articlesvehicletrees | 651M | PARTIAL — not in enrichment |
| articlecriteria | 27M | NO — specs never returned |
| articledocs | 8.2M | NO — images never returned |
| replacedbyarticles | 229K | NO — supersession never returned |
| replacesarticles | 240K | NO |
| legacy2generic | 6.2M | NO — functional equivalents never returned |

The fix is 5-7 days of Go engineering, zero new data licensing.

## 7. How the Current Search Works

User query → smart_search.go Search()

For OEM numbers — 9-strategy cascade:
1. CrossRef.FindByOEM (Postgres oem_search_index ~1,700 rows)
2. OEMLookup.Search (same Postgres table)
3. TecDoc.SearchByOEM (MySQL oem_number 21.5M rows) ← works well
4. Strip color suffix → retry step 1
5. Prefix fuzzy LIKE prefix%
6. PartsOuq scrape (online HTML)
7. Dealer scrape (hyundaipartsdeal.com, kiapartsnow.com)
8. Reverse supersession from cache
9. tecdoc_keyword ← BUG: returns garbage when all above miss

For text queries → searchByText() → tecdoc_keyword → BUG-1, BUG-2

Confidence scoring is keyword-classification-based only:
- FitUniversal → 0.90
- FitEngine    → 0.70 without CC, 0.95 exact CC match
- FitBrake     → 0.75 without CC
- FitBody      → 0.85
- tecdoc_keyword → 0.65 (garbage sentinel)

No specification matching, no dimensional equivalence, no supersession,
no compatibility list, no images in output.

## 11. Architecture Decisions Documented

IsHKOEM vs looksLikeOEMNumber:
- looksLikeOEMNumber: permissive, for search routing, accepts digit-first + dash + 4 digits
- IsHKOEM: strict, checks 2-digit prefix against 78-entry HK OEM prefix set,
  rejects Toyota 90915, BMW 11427, Honda 15400
- Known limitation: Mercedes 271 180 02 10 prefix "27" collides with HK Engine range

tecdoc_keyword confidence sentinel:
- Confidence exactly 0.65 = "returned by keyword fallback" = likely wrong category
- All quality tests use minConfidence > 0.65 to reject these

Category classification is keyword-only:
- ClassifyCategory(description) does substring matching against 80 English keywords
- HK internal descriptions ("PUMP ASSY-WATER") don't match (reversed word order)
- These get FitUniversal (0.90) instead of FitEngine (0.70)
- Documented as known data quality gap
