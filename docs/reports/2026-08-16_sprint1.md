## Notes for the reviewer

1. **Pattern:** each new service takes a small injectable repo interface (`crossRefRepo`, `specificationRepo`, etc.) rather than a raw `*sql.DB`. Production wire-up uses `sqlXxxRepo{db}` backed by the existing `logQueryCtx` helper from `dblog.go`. Tests inject stubs. This mirrors `supersession.go`'s `substitutionLinkFinder` shape, which was the only pre-existing testable service.
2. **Provenance stamps:** every returned row carries a `Source` / `LicensedSource` / `Manufacturer` value that identifies its TecDoc origin table (`tecdoc:articlecriteria`, `tecdoc:articledocs`, `tecdoc:articles`, `functional:legacy2generic`). This is a preemptive fix for the `BUGS.md` warning that specifications / documents / supersession must not be presented as manufacturer-confirmed unless the source can prove it.
3. **Depth-capped supersession:** the recursive walker enforces `MaxSupersessionDepth = 10` in Go rather than via a MySQL `WITH RECURSIVE` clause. Rationale: the cap logic and cycle detection must be unit-testable without a live database. If a perf regression appears in production, swap `sqlSupersessionRepo` for a `WITH RECURSIVE` version — the interface does not change.
4. **No changes to existing files.** All 13 files are new. Existing `tecdoc.go`, `crossref.go`, `supersession.go` are untouched, and the pre-existing `TestSupersessionPreservesImportedSourceCaution` still passes.
5. **Integration TODO (out of Sprint 1 scope, tracked here):**
   - Wire the seven `NewTecDoc*` constructors into `cmd/api` / `cmd/qa_gate` startup so real handlers can call them.
   - Add MySQL-backed integration tests (or `sqlmock`) for the seven `sql*Repo.Query*` methods.
   - Add these seven services to the SmartSearch dispatch table when Sprint 2 lands.
