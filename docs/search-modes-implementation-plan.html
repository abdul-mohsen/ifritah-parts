ifritah-parts / qa.ifritah.com | Engineering roadmap | User-selectable search modes + Smart Search combined mode

Executive Summary

The database has 14 TecDoc tables loaded (30M cross-refs, 27M specifications, 8.2M documents, 651M vehicle linkages, 229K supersession chains). The current Go service queries only 2 of them. This plan exposes each unused table as a selectable search strategy in the UI, plus a Smart Search mode that combines all strategies with weighted scoring.

Search Modes — User-Selectable Strategies

User picks a mode from a dropdown next to the search box. Each mode uses a different TecDoc table + query strategy.

Frontend dropdown mock-up — Stage 5 deliverable

Mode 1 · Fastest

Exact OEM Match

Direct hash lookup by normalized OEM number. Sub-100ms response. Highest confidence when hit.
Tables: oem_number (21.5M) + articles
Query: WHERE clean_number = ?
Confidence: 0.95
Best for: User types full OEM they already know
Mode 2 · Widest brand coverage

Cross-Reference (Aftermarket)

Query the 30M-row cross-reference index. Returns 30–50 aftermarket alternatives per OEM.
Tables: articlecrosses (30M) + articles + ambrand
Query: WHERE oemNumber = ? ORDER BY brandName
Confidence: 0.85
Best for: Finding cheaper brand alternatives
Mode 3 · By vehicle

Vehicle Fitment Search

Find every part that fits a specific vehicle. Uses the 651M-row vehicle-tree table.
Tables: articlesvehicletrees (651M) + linkagetargets + assemblygroupnodes
Query: WHERE linkingTargetId = ? AND assemblyGroupNodeId = ?
Confidence: 0.90 (verified fit)
Best for: Browse parts by known car (VIN + category)
Mode 4 · By dimensions

Specification Search

Match by physical specs (thread size, diameter, capacity). Uses the 27M-row criteria table.
Tables: articlecriteria (27M) + criteria + keyvalues
Query: Multi-criteria AND with tolerance ranges
Confidence: 0.80
Best for: Universal parts (bolts, hoses, filters) where physical fit matters
Mode 5 · Same role

Functional Equivalents

Same-generic-type parts that fit the same vehicle. Different brand, same function.
Tables: legacy2generic (6.2M) + genericarticlesgroups
Query: Match by genericArticleId + vehicle constraint
Confidence: 0.85
Best for: "Show me all oil filters that fit this Tucson"
Mode 6 · Chain forward/back

Supersession Chain

"This part is replaced by X" or "X replaces this part". Recursive traversal.
Tables: replacedbyarticles (229K) + replacesarticles (240K)
Query: Recursive CTE, depth ≤10
Confidence: 0.95 (direct OEM chain)
Best for: Discontinued part → find current replacement
Mode 7 · Cross-brand

Hyundai ↔ Kia Platform

Tucson/Sportage, Elantra/Forte, Sonata/K5 share parts. Discover cross-brand fits.
Tables: articlesvehicletrees self-join across manufacturers
Query: Pre-computed platform_pairs table (offline job)
Confidence: 0.90
Best for: Kia Sportage owner searching for cheaper Hyundai Tucson OEM number
Mode 8 · Fallback only

Keyword Fulltext

FULLTEXT search over combined keywords. Only when no OEM number is available. Category-gated.
Tables: searchindex (5.8M MyISAM FULLTEXT)
Query: MATCH(keywords) AGAINST(? IN BOOLEAN MODE)
Confidence: 0.65 (sentinel value)
Best for: Text queries like "oil filter" without a specific part number
Mode 9 · Recommended · Default

🚀 Smart Search — Combined

Runs modes 1–7 in parallel, merges results with weighted scoring, dedupes, and ranks by combined confidence. Falls back to Mode 8 only if all others miss.
Tables: All 14 TecDoc tables
Query: Fan-out over 7 goroutines, merge with priority queue
Confidence: Weighted combination (0.95 exact>0.90 xref>0.85 equiv...)
Best for: Default user experience — maximum coverage & accuracy

Sample: SearchCrossReferences

// SearchCrossReferences returns aftermarket alternatives for an OEM number
// by querying the 30M-row articlecrosses table directly.
func (t *TecDoc) SearchCrossReferences(ctx context.Context, oemNumber string, limit int) ([]model.OEMReference, error) {
    ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
    defer cancel()

    query := `
        SELECT
            ac.oemNumber, ac.legacyArticleId, ac.brandName, ac.number,
            a.articleNumber, a.genericArticleDescription
        FROM articlecrosses ac
        JOIN articles a ON a.legacyArticleId = ac.legacyArticleId
        WHERE ac.oemNumber = ?
        ORDER BY ac.brandName
        LIMIT ?`

    rows, err := logQueryCtx(t.db, ctx, "TecDoc.SearchCrossReferences", query, oemNumber, limit)
    if err != nil { return nil, err }
    defer rows.Close()

    var refs []model.OEMReference
    for rows.Next() {
        var ref model.OEMReference
        if err := rows.Scan(&ref.RawNumber, &ref.LegacyArticleId, &ref.BrandName,
            &ref.ArticleNumber, &ref.OriginalArticleNumber, &ref.Description); err != nil {
            continue
        }
        ref.Manufacturer = "CROSSREF"
        refs = append(refs, ref)
    }
    return refs, nil
}

Design: Strategy Pattern

// SearchStrategy is the common interface every mode implements.
type SearchStrategy interface {
    Name() string                                           // "exact_oem" | "cross_ref" | ...
    Confidence() float64                                    // base confidence score
    Search(ctx context.Context, req SearchRequest) (*SearchResult, error)
}

type SearchRequest struct {
    Query            string
    LinkageTargetId  int
    VehicleCC        int
    FuelType         string
    Category         string
    Specifications   []model.SpecCriteria  // for mode 4 (spec search)
    Page, Limit      int
}

type SearchResult struct {
    Results          []SmartResult
    Total            int
    Strategy         string
    Latency          time.Duration
    Warnings         []string
}

Category-token gate for keyword mode (fixes BUG-1)

// KeywordFulltextStrategy prevents "oil filter" → "Fuel filter" false positives
// by requiring the returned description to contain expected category tokens.
func (s *KeywordFulltextStrategy) Search(ctx context.Context, req SearchRequest) (*SearchResult, error) {
    rawResults, err := s.tecdoc.SearchByKeyword(req.Query, req.Limit*3)
    if err != nil { return nil, err }

    expectedTokens := s.categoryTokensFor(req.Query)  // "oil filter" → ["oil", "filter"]
    filtered := make([]model.OEMReference, 0, len(rawResults))
    for _, r := range rawResults {
        if containsAllTokens(r.Description, expectedTokens) {
            filtered = append(filtered, r)
        }
    }
    return &SearchResult{Results: filtered, Strategy: "keyword_gated"}, nil
}

Stage 4 — Smart Search Combined Mode

Stage 4

Fan-out over 7 strategies, merge/rank/dedupe results

4 days · 1 backend engineer

Depends on: Stage 2 (strategies) + Stage 3 (API)

Algorithm

func (s *SmartSearch) SmartCombined(ctx context.Context, req SearchRequest) (*SearchResult, error) {
    ctx, cancel := context.WithTimeout(ctx, 3*time.Second)  // hard budget
    defer cancel()

    // Fan-out: run 7 strategies in parallel
    type stratResult struct {
        strategy string
        results  []SmartResult
        err      error
        latency  time.Duration
    }
    ch := make(chan stratResult, 7)
    strategies := []SearchStrategy{
        s.reg["exact_oem"], s.reg["crossref"], s.reg["vehicle"],
        s.reg["functional"], s.reg["supersession"], s.reg["crossbrand"],
        s.reg["spec"],
    }
    for _, strat := range strategies {
        go func(st SearchStrategy) {
            start := time.Now()
            r, err := st.Search(ctx, req)
            ch <- stratResult{st.Name(), r.Results, err, time.Since(start)}
        }(strat)
    }

    // Collect (up to 3s each; skip on error/timeout)
    var allResults []SmartResult
    strategiesUsed := []string{}
    for i := 0; i < 7; i++ {
        select {
        case r := <-ch:
            if r.err == nil && len(r.results) > 0 {
                allResults = append(allResults, r.results...)
                strategiesUsed = append(strategiesUsed, r.strategy)
            }
        case <-ctx.Done():
            // Global timeout — return what we have
            goto merge
        }
    }
merge:
    // Merge/dedupe by legacyArticleId, keep highest confidence
    merged := dedupeByArticleId(allResults, keepHighestConfidence)

    // Rank by combined confidence:
    //   score = strategyConfidence * strategyPriority * matchBonus
    //   priorities: exact_oem=1.0, crossref=0.9, vehicle=0.85, functional=0.8, ...
    sort.Slice(merged, func(i, j int) bool {
        return combinedScore(merged[i]) > combinedScore(merged[j])
    })

    return &SearchResult{
        Results: merged[:min(req.Limit, len(merged))],
        Total:   len(merged),
        Strategy: "smart_combined",
        StrategiesTried: strategiesUsed,
    }, nil
}

Risks & Mitigations

RISK 1 — 651M-row articlesvehicletrees join is expensive

Vehicle Fitment and Cross-brand modes could produce > 5s queries under load.

Mitigation: Pre-compute platform_pairs materialized table (Stage 1). Add per-vehicle Redis cache in Stage 7 (Tier 1 optimization).

RISK 2 — Keyword mode still produces junk without a strict gate

Without category-token gate, mode 8 will return wrong-category results (BUG-1 style).

Mitigation: Category-token gate is mandatory (Stage 2.8). If < 2 tokens match, drop the result. Confidence sentinel 0.65 tells UI to warn user.

RISK 3 — Smart Search parallel fan-out could stress MySQL

7 concurrent queries per user request; 100 concurrent users = 700 concurrent MySQL queries.

Mitigation: Connection-pool cap at 20; circuit breaker (Stage 4.6); Redis cache for hot vehicles.

RISK 4 — Response payload gets too large

Full enrichment can push 30-part response past 500KB. Slow on mobile.

Mitigation: enrichmentLevel=basic|full param (Stage 3.5). Default basic. Frontend fetches full on card expand.

⚠ Not in scope of this plan
  • Loading missing HK OEMs into TecDoc (e.g. 58101-D3A70) — this is data-side work, not code.
  • New brand catalog integrations (MANN, BOSCH, MAHLE APIs) — Tier 3 follow-up after this plan lands.
  • ML-based fitment ranking — reserved for post-launch iteration.
